### 生成代码和已验证差异


`u8x16 × 4`：四个 16 lane 比较先按位 OR，再 `.any()`。ARM 实际库每块由手写版 `2×LDP` 变为 `LDP + 2×LDR`，比较仍是 `4×CMEQ + 3×ORR + ADDP + FMOV`；每个扫描块增加 1 条动态指令。长 char 查询约 40 个块，动态 instructions 增加约 40，cycles 同步变差。载入顺序、排程及内部循环地址也变动，未独立排除其贡献。x86 两版均为 `4×MOVDQU + 4×PCMPEQB + 3×POR + PMOVMSKB`，指令数量相同而排程可不同。

`u8x64`：孤立返回 bool 的核心能生成两条 LDP、四次比较、三次 ORR 和 UMAXV；但实际扫描函数的前缀和循环分支退化为 64 位 mask 打包，出现 `4×AND + 12×ADDP + 4×UMOV` 后才做标量归约/判断；尾部返回路径仍能保持精简。因此孤立探针的好汇编不能代表完整标准库。

包含扫描循环的独立复现 `scan_any64.rs/.ll/.s` 重现此差异：前缀/循环 IR 是 `bitcast <64 x i1> ... to i64` 后 `icmp eq ... 0`，尾部是 `icmp ne ... 0`。已定位为当前 LLVM AArch64 生成代码问题；未定位到具体 pass，不将旧版本的 pass 结论直接套用。32 lane 的 any/整数 min 归约仍有打包；64 lane 改整数 min 同样未消除；16 lane 整数 min 及平衡 OR 写法仍未恢复两条 LDP。这些仅为生成代码对照，没有宣称其未测性能。

### portable 实验代码


以下 helper 保持原有 AArch64 NEON / x86_64 SSE2 cfg 门槛。扫描函数和公开 API 保持先前实现。

```rust
fn contains_byte_64(c: &[u8], needle: u8) -> bool {
    use crate::simd::cmp::SimdPartialEq;
    use crate::simd::u8x16;

    assert_eq!(c.len(), 64);
    let n = u8x16::splat(needle);
    let a = u8x16::from_slice(&c[..16]).simd_eq(n);
    let b = u8x16::from_slice(&c[16..32]).simd_eq(n);
    let d = u8x16::from_slice(&c[32..48]).simd_eq(n);
    let e = u8x16::from_slice(&c[48..64]).simd_eq(n);
    (a | b | d | e).any()
}
```

### 证据和重现入口


`analysis/repro/contains-portable-simd-20261105/` 为 u8x16×4，`analysis/repro/contains-portable-simd64-20261105/` 为 u8x64；各自 common 保存源文件、源码差异、构建脚本和日志，aarch64/x86_64 保存原始 perf/libtest 输出、汇总 JSON、二进制、实际库汇编和运行时 libstd。完整静态 sysroot 留在两机对应 `/tmp/contains-*/sysroots`，其 SHA256 清单随档案保存。原始库源码快照、Cargo/linker provenance 和 bootstrap 配置见前一实验 common，避免复制失去对应关系。

两候选使用 `./x build --stage 0 library/std library/test --target aarch64-unknown-linux-gnu,x86_64-unknown-linux-gnu`；测试使用 `./x test --stage 0 --set build.compiletest-allow-stage0=true library/coretests library/alloctests --target aarch64-unknown-linux-gnu --test-args str::`。在各自 /tmp 实验目录运行 `python3 build-harness.py baseline check custom-check benches matrix counted`、同样的 optimized，再在对应架构机器运行 `python3 run-final.py` 和 `python3 collect-final.py`；命令中的 compiler/sysroot/linker 绝对路径须保留或相应调整。性能脚本保存每次 perf 原始输出，summary JSON 提供每项三次范围及详细计数。独立 scanner 复现与孤立 helper 的 Rust、IR、汇编在 common 内保存，scanner 精确编译命令见 common/diagnostic-commands.json。

这次证明可以用 core::simd 完整替换手写指令核心并保留 contains 语义；没有证明 portable 写法具有普遍性能优势。u8x16×4 比 u8x64 更稳妥，但当前 ARM 长扫描仍逊于手写版，不能把它称为新的整体性能优化。
