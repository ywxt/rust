# 短字符串探针未覆盖内部差异字节，搜索退回 Two-Way

`str::bench_contains_bad_simd` 查询 74 个 `a` 中是否包含 `aaabaaaa`，预期结果为 `false`。当前实现只在 needle 末尾四字节中寻找第二探针，遗漏了下标 3 的 `b`，随后退回逐字节的 Two-Way 搜索。ARM 和 x86 都执行这条回退路径，ARM 的每次查询周期、动态指令和分支预测失败次数更高。

**接口内扩大探针范围能显著改善本用例，但存在其他输入回退，尚不能作为无条件的通用优化。** 原 benchmark 的输入、屏障、断言及查询流程均保留；8 个原始 contains benchmark 的函数体已逐项按 token 核对。改动仅位于隔离标准库的 `library/core/src/str/pattern.rs`，本任务未修改远程原仓库的接口文件和 benchmark。

## 基线与执行路径

本轮基于分析开始时冻结的接口源码，使用同一 rustc 1.99.0-dev、LLVM 23.1.0 重建 ARM、x86 的标准库和 test 库。ARM 为 HiSilicon 服务器 CPU 52，x86 为 i7-12700 P 核 CPU 12；默认目标特性分别包含 NEON、SSE2。编译器提交字段为 `unknown`，源码副本的 Git HEAD 为 `dc55da5cca14a0aa773ecb7a0459756260b2ee5c`，继承了当前已有的 library 修改。完整输入 SHA、构建命令和 sysroot 清单见 [复现说明](README.md)。此前 rustc 1.101 缓存结果未混入本轮前后对照。保存报告时检测到外部将单字节辅助函数 `contains_byte_64` 改为 portable SIMD；本轮四组实验均采用该更新前的同一快照。该改动未改变本用例的多字节探针逻辑，但下述整库测试数字不直接代表外部更新后的版本，差异已归档。

原始查询：

```rust
let haystack = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa";
let needle = "aaabaaaa";
assert!(!black_box(haystack).contains(black_box(needle)));
```

接口路径为 `str::contains` → `<&str as Pattern>::is_contained_in` → `simd_contains` 尝试选择探针 → `StrSearcher::new` → Two-Way 搜索。ARM 已有 NEON 实现；本用例在进入向量扫描前返回 `None`。

| 探针选择 | 实际内容 | 结果 |
|---|---|---|
| 首字节 | `needle[0] = a` | 第一个探针为 `a` |
| 末尾四字节 | `needle[4..8] = aaaa` | 找不到不同于首字节的字符 |
| 被遗漏的字节 | `needle[3] = b` | 可以作为有效第二探针 |

可独立编译的 [probe-selection.rs](common/probe-selection.rs) 验证旧范围返回 `None`、完整范围返回 `Some(3)`，并调用原 `str::contains` 核对结果。原函数并未执行 16 字节分块比较，因此原用例的差距不能归因于这一阶段的 SIMD 掩码提取。

| 成因 | 成立范围与具体行为 | 对应接口方法 |
|---|---|---|
| 算法路径选择 | 两平台均因末尾四字节没有差异字符而回退；本输入执行 14 轮标量校验 | 在 `simd_contains` 内扩大第二探针范围；有重复文本、准备成本回退 |
| SIMD 掩码提取的指令差异 | 已进入 SIMD 时，x86 使用 `pmovmskb`，当前 ARM 使用多条指令构造位置掩码；原用例基线未执行此阶段 | 合并空候选判断，命中后再提取位置；单独用于本用例基线无算法收益 |

## 回退路径执行了什么

Two-Way 对 `aaabaaaa` 计算得到分界位置 4，采用长周期路径，失败后推进 5 字节：

```text
needle = aaab | aaaa
               ↑ 先从右半部分开始比较
```

在全为 `a` 的 haystack 中，每轮右半部分的四个 `a` 都匹配，随后向左检查到 `b` 时失败。候选起点依次为 `0, 5, 10, …, 65`，共 14 轮、70 次逐字节相等比较；此外还有尾字节集合检查和每次调用的 needle 预处理。完整算法跟踪见 [algorithm-trace.json](common/algorithm-trace.json)。采样确认原调用进入 `StrSearcher::new`，主要热点位于标量搜索及其准备过程。

ARM 的标量比较循环使用两条 `ldrb` 加 `cmp`，x86 可用一次加载和带内存操作数的 `cmpb`。两端还有循环控制、尾字节集合测试和左右半段切换。固定次数对照中，ARM 每次查询比 x86 多约 54 条动态指令，分支预测失败约为 2.00 次与 0.51 次。这些成本随接口内的路径切换一并减少；各组指令与预测失败的独立周期份额尚未拆分。

| 固定次数执行原查询体，用户态计数/次 | ARM | x86 |
|---|---:|---:|
| cycles | 285.98 | 226.57 |
| instructions | 1283.26 | 1229.66 |
| branches | 323.06 | 310.13 |
| branch-misses | 2.0035 | 0.5063 |

该驱动用于直接计数，保留原查询体，替换了自适应计时框架；其周期不能与原 libtest 时间直接换算。原 libtest 基线为 ARM **101.68 ns**、x86 **49.64 ns**。ARM/x86 查询周期比为 **1.262**，原框架耗时比为 **2.048**；两台机器还存在约 2.9 GHz 与 4.5 GHz 的运行频率差异。

## 接口内修改方法

### 扩大第二探针的选择范围

仅修改 `simd_contains` 内部的选择范围，公共接口和调用端保持不变：

```diff
- (needle.len().saturating_sub(4)..needle.len()).rfind(|&idx| needle[idx] != first_probe)
+ (1..needle.len()).rfind(|&idx| needle[idx] != first_probe)
```

本接口的 SIMD 分支仅处理长度不超过 32 的短 needle。新的范围找到下标 3 的 `b`，继续使用现有 NEON/SSE2 扫描。haystack 中没有 `b`，候选向量全部为零，查询可以跳过 Two-Way 预处理和 14 轮标量校验。

所有有效第二探针仍满足 `1 <= offset < needle.len()`；现有加载边界按 `needle.len() - 1` 留出空间，边界条件保持。两个字节的特殊分支、全相同 needle 的回退及候选命中后的完整校验仍保留。

### 合并空候选判断，按需提取位置掩码

对已经进入 SIMD 的路径，另做单项与组合实验：`test_chunk` 返回向量掩码，先合并四块判断是否有候选，命中后再提取各块的位掩码。

```rust
if (masks[0] | masks[1] | masks[2] | masks[3]).any() {
    for j in 0..UNROLL {
        let mask = masks[j].to_bitmask() as u16;
        if mask != 0 {
            result |= check_mask(i + j * Block::LEN, mask, result);
        }
    }
}
```

x86 的位置掩码由 `pmovmskb` 提取；当前 ARM 生成的完整位置掩码使用位权常量及多次 `addp`、`umov`。零候选时只需布尔判断，四块合并可减少位置掩码的构造。实际 ARM 组合版本生成三次向量 `orr`，随后 `addp d1, v1.2d`、`fmov`、`cbz`，没有生成 `umaxv`。

对应优化后 IR 节选如下，完整内容见 [组合版本 IR](arm/combined/aarch64-unknown-linux-gnu/benches.ll)：

```llvm
%self7119.i = or <16 x i1> %_4011.i.i, %_4011.i.1.i
%self9120.i = or <16 x i1> %self7119.i, %_4011.i.2.i
%self11121.i = or <16 x i1> %self9120.i, %_4011.i.3.i
%89 = bitcast <16 x i1> %self11121.i to i16
%_55.not.i = icmp eq i16 %89, 0
br i1 %_55.not.i, label %bb23.i, label %bb65.preheader.i
```

原用例的基线在选择探针时已经回退，因此单独调整掩码处理不会减少它的算法工作。该实验同时用于检查进入 SIMD 后的剩余成本，不能将其收益记入原回退路径。

## 双平台结果

以下为 3 轮交错测量的中位数。各版本均重建实际标准库，再编译相同查询体；没有以外部替代函数覆盖调用端。

| 原 benchmark，ns/次 | ARM | x86 |
|---|---:|---:|
| 基线 | 101.68 | 49.64 |
| 扩大探针范围 | 25.65 | 5.14 |
| 只合并空候选判断 | 98.03 | 54.78 |
| 两项组合 | 25.59 | 5.13 |

扩大探针范围在原 benchmark 中使 ARM 耗时下降 **74.8%**、x86 下降 **89.6%**。基线范围为 ARM 96.26–101.87 ns、x86 49.00–49.84 ns。单独合并空候选判断没有改变此输入的回退路径，x86 仍测得约 10.4% 回退；此项变化不能解释为搜索算法收益。

固定次数对照单独记录如下：

| 同查询体的 cycles/次 | ARM | x86 | ARM/x86 周期比 |
|---|---:|---:|---:|
| 基线 | 285.98 | 226.57 | 1.262 |
| 扩大探针范围 | 28.26 | 23.83 | 1.186 |
| 只合并空候选判断 | 286.76 | 248.51 | 1.154 |
| 两项组合 | 24.97 | 23.83 | 1.048 |

合并判断在固定次数复现中相对扩大探针版本降低 ARM 周期约 11.6%，原 libtest 中没有明显附加收益。两类驱动的调用上下文不同，结论分别保留。源码改动尚未消除原框架中 ARM 的全部额外成本。

## 场景覆盖与回退

两台机器、四个版本各通过 **1,096,990** 组独立字符串对照。包括二元字母表穷举、随机 Unicode、NUL，以及性能场景的逐项校验。预期值由字节窗口直接比较产生，未使用修改后的 `contains` 计算预期。

性能检查包括 28 项完整 libtest 测试，以及每平台 **973** 个补充场景、每项 3 轮：needle 长度 0/1/2/3/4/5/8/16/32/33，haystack 长度 0–4096 的多个边界值，内部差异字节的各个位置，首/中/尾命中和未命中，地址偏移 0/1/15/63，全相同字符、重复文本、Unicode 和 NUL。

以下补充场景使用循环内线程 CPU 时间，单位 ns/次，排除了进程准备和调度等待；它们是独立输入矩阵，不替代原 benchmark：

| 输入场景 | ARM 基线 → 扩大探针 | x86 基线 → 扩大探针 |
|---|---:|---:|
| needle=`aaabaaaa`，4096 字节交替 `ab` 文本 | 3574.19 → 4475.37（**+25.2%**） | 1583.39 → 2257.76（**+42.6%**） |
| needle=`aaabaaaa`，256 字节交替 `ab` 文本 | 258.86 → 299.46（**+15.7%**） | 123.47 → 146.10（**+18.3%**） |

全相同 needle 会增加准备阶段的扫描：长度 32 时旧范围检查 4 字节，新范围检查 31 字节，随后仍然回退。重复 `ab` 文本中，扩大范围选到的 `b` 会产生大量候选；候选通过两个探针后，仍需完整校验，原 Two-Way 的跳过机制在这些输入上更有效。这两类回退具有明确的算法原因。

扩大探针范围在 ARM 的 973 个场景中有 41 项回退超过 5%，x86 为 104 项；组合版本分别为 40 项与 95 项。部分短输入或未改变算法的分支也存在生成代码、布局和测量变化，不能全部记到探针扫描上。合并判断的 x86 密集候选场景最大回退约 72.8%，因此也不能作为跨平台无条件改法。

全部 28 项测试及 973 个场景的收益、无收益、回退和样本范围保存在 [相关测试](related-benchmarks.md) 与 [输入矩阵](scenarios.md)。当前仅验证两台 CPU、默认目标特性和重复热数据，尚未验证冷缓存、其他 CPU、native/LTO 配置。

## 测量条件与 LLVM 诊断

- 最终 perf 进程及被测进程均提前绑到目标核心；硬件事件运行占比全部为 100%。早期 x86 记录的事件运行占比不足，已单独保留；最终周期表不使用这些记录。
- 两个平台对被测进程关闭 ASLR，保存输入、源码、动态库和程序校验值。所有性能阶段在每台机器上顺序执行。
- 原 libtest 中，扩大探针版本的 ARM 输入 `black_box` 使用不同于固定次数驱动的栈槽。仅改变应用侧 LLVM 选项，`-no-stack-coloring` 得到约 9.90 ns，`-aarch64-enable-ldst-opt=false` 得到约 10.16 ns；x86 的 `-no-stack-coloring` 为 5.67 ns，相对默认 5.13 ns 回退约 10.5%。选项不修改接口源码，也没有重编已保存的 sysroot。
- 独立汇编探针进一步覆盖 8 种地址模 64 偏移。ARM 的 `stp/ldp` 依赖链在偏移 24/56 时约 9.18/9.29 cycles，其余约 6.89；拆分读取后约 7.49。该结果确认了一类跨界写读成本，但不足以解释原框架与固定次数驱动的全部差值。

关闭栈槽复用会改变栈帧和地址；关闭配对优化会影响其他加载、写入及向量路径。以上为诊断结果，未完成全程序验证，不列为已验证的接口修法。原 benchmark 的正确性和输入保持有效，本轮没有修改它的依据。

本次的明确结论是：**末尾四字节的探针范围遗漏内部差异字节，导致本用例退回多轮标量搜索；接口内扩大范围可减少该成本，但重复文本和全相同 needle 存在回退。** ARM 相对 x86 的完整耗时差仍受执行频率、生成代码和调用上下文影响，已有 NEON 路径的可用性已确认。
